## 目标与范围

来源：用户视角盘点的第二梯队（每天都会别扭的那批），只做 Android。八条：

1. 阅读器没有沉浸模式，顶栏 + 底栏永久压在画面上（约一成高度）。
2. 阅读设置里「页间距」「亮度」两条滑块没有标题，只能靠拖动气泡猜。
3. 阅读器把任何故障都显示成核心的内部异常串（`page 7 unavailable: ...`）。
4. 搜索时每敲一个字符整面墙先清空闪「共 0 个 Series」，没有清除按钮，零命中不给提示。
5. 书架滚到底没有「已经到底了」，追加失败的提示渲染在列表顶部（用户停在底部看不到）。
6. 冷启动标题是英文 `Library`；刚连上服务器但库里没数据时误报「未连接服务器」，还把「立即同步」藏起来。
7. 下载队列停摆只认 `linkBlocked` 一种原因，其它一律显示「排队中」；没有一次清空入口；首次读失败静默成「还没有下载」。
8. 首次加服务器：不知道 API Key 从哪来；改了地址/Key 仍可保存未验证的配置；编辑时换个名字也得重输 Key。

明确排除：iOS/macOS 侧、阅读模式按系列记忆（Android 已有 per-series 覆盖，属入口优化）、诊断页 `lastError`/墓碑、本地库重建入口——属第三梯队。

## 已确认决定

- **沉浸**：阅读器默认只有画面；点「中间带」显示/收起上下栏，中间带永不翻页；轴向跟随 core 的 `tapNext`（横排取宽的 30%–70%，纵向取高的 30%–70%）；条漫同样用中间带唤出工具栏（否则滚动阅读再也进不了设置）。不改系统状态栏，不做动画。
- **错误**：controller 保留结构化 `failure`（对象），`error` 降级为诊断文本只进日志与压力报告；UI 一律走 `FailurePresentation`。
- **搜索**：输入变化保留上一批结果（只作废旧请求 + 顶部进度条）；清除按钮只清关键词，不重置图书馆/状态/标签/题材筛选。
- **空态三态**：「没有服务器」按激活 profile 判断，不再按未读取的标题判断；有服务器未同步 → 主按钮「立即同步」；有服务器且同步过但库空 → 说明去 Komga 加内容。
- **下载**：`stopReason` 的 16 个取值在 UI 侧全覆盖，未知值给中性文案而不打印标识符；「还在推进」的原因不出状态条；「全部删除」只删本服务器下载，二次确认里写明册数与字节数。
- **服务器表单**：Key 留空 + 编辑态 = 沿用 Keystore 里已保存的 Key；地址或 Key 改动后，上次的测试结果作废、保存重新变灰；空 Key 直接在字段上提示，不发请求。
